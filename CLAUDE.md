# Working conventions for this repo

- After any change to the code or architecture, update `README.md` if the change affects something it documents (folder structure, design decisions, what was left out, open questions, test count, setup/deploy steps). Do this proactively, without being asked each time.
- Keep the README's "### Folder structure" tree block in sync with the actual `src/`, `api/`, `web/src/app/`, `tests/` layout.
- Document real design decisions and trade-offs in "## Design decisions" as they're made, not just when explicitly asked to write documentation.
